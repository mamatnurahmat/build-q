# build-q v0.2.6

Rilis patch: **`--manifest-init --pr`** mengajukan saran manifest langsung sebagai PR ke repo
GitOps, dan **analisa source aplikasi** membuat saran YAML mengikuti cara aplikasi benar-benar
membaca config: bahasa → format file, Dockerfile → path file, kode .NET → cara environment
diberikan. Desain: [PRD-manifest.md §5.6](../PRD-manifest.md); panduan:
[E2E-MANIFEST.md §14](../E2E-MANIFEST.md).

## New

### 📦 `bq --manifest-init <repo> <namespace> --pr`

```bash
bq --manifest-init pay-be-topup-manager develop-qoin --pr --dry-run   # pratinjau
bq --manifest-init pay-be-topup-manager develop-qoin --pr             # branch + PR
```

- Satu commit di branch baru `manifest/<app>-<folder>-<waktu>` (GitHub Git Data API, tanpa clone),
  lalu PR ke branch GitOps env (develop/staging/sandbox atau `main`). Tidak pernah push langsung.
- Isi: Deployment/Service baru atau perbaikan (hanya file yang berubah).
- `kustomization.yaml`: **hanya baris `resources` yang ditambahkan**, dengan indentasi item terakhir;
  komentar, `patches`, dan key lain tidak disentuh. Hasilnya di-parse ulang, dan kalau ada yang ikut
  berubah (mis. `resources: [a, b]` inline) PR dibatalkan. Folder baru → `kustomization.yaml` baru.
- **Secret tidak pernah di-commit**: saran Secret dibuang (dicatat di deskripsi PR) dan file
  `kind: Secret` / bernama `*secret*` ditolak.

### 🔎 Analisa source aplikasi di `--manifest-init`

- **Bahasa → format file config**, deteksi berlapis dengan bukti: `STACK`/`TYPE` cicd.json →
  file penanda root (`*.csproj`/`*.sln`/`appsettings*.json`, `go.mod`, `Cargo.toml`, `package.json`,
  `requirements.txt`/`pyproject.toml`) → base image Dockerfile (termasuk `krakend`) → GitHub
  Languages API. **.NET → `appsettings.<env runtime>.json`, bahasa lain → `.env`.**
- **Path file config ← Dockerfile stage final**: tujuan `COPY … .env`, selain itu `WORKDIR`
  (tanpa WORKDIR = `/`, diwarisi lewat alias stage). Contoh: `plus-be-appmerchant-manager` →
  `/.env`; aplikasi `WORKDIR /app` → `/app/.env`.
- **Mode environment .NET ← `Program.cs`/`Startup.cs`**: nilai `GetEnvironmentVariable(
  "ASPNETCORE_ENVIRONMENT"|"DOTNET_ENVIRONMENT")` dipakai dalam logika → env
  `ASPNETCORE_ENVIRONMENT` (mis. `ngenwal-be-transactionconverter-manager`); selain itu → args
  `dotnet <app>.dll --environment=<env>` (mis. `ngenwal-be-saasidentityserver4client-manager`).
  Mount dan key Secret selalu `appsettings.<env runtime>.json`. Pola di params rule
  `dotnet_env_mode` (PB), bisa ditambah tanpa rilis.

### 🧩 Rule baru

| Rule | Severity | Di mana | Deteksi |
|---|---|---|---|
| `appsettings_env_mismatch` | critical | semua (manifest) | env runtime .NET ≠ `appsettings.<X>.json` yang di-mount → config diabaikan |
| `config_mount_path_mismatch` | critical | `--manifest-init` | file config di-mount di direktori yang tidak dibaca aplikasi (menurut Dockerfile); disertai saran Deployment terkoreksi |
| `config_format_mismatch` | critical | `--manifest-init` | .NET me-mount `.env` tanpa DotNetEnv/dotenv.net, atau non-.NET me-mount `appsettings` |

Total rule di PB `build_q_anomaly_rules`: 57.

## Improved

- Generator: mode env .NET mendukung `args`, `env`, `args+env`, dan tanpa keduanya; env var .NET
  dibuang saat target bukan .NET; aplikasi .NET dengan config baked yang hanya punya env
  `ASPNETCORE_ENVIRONMENT` dikenali sebagai .NET.
- `--manifest-verify` juga membandingkan mode dan env runtime .NET.
- Dockerfile dibaca per stage (stage final + warisan alias), bukan WORKDIR terakhir di file.
