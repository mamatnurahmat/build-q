# build-q v0.2.6

Rilis patch: **login SSO ArgoCD** dari bq dengan token yang terpusat di PocketBase, serta
pemakaian official `argocd` CLI secara inline. Penyimpanan lokal hanya di `~/.build-q/auth.json`.

## New

### 🔐 `bq --argocd-auth-sso`

Login SSO ArgoCD via browser (GitHub org), memakai official `argocd login` dengan `--config`
sementara sehingga tidak menulis ke `~/.config/argocd`. Alur: login → verifikasi `userinfo`
(`loggedIn` harus `true`) → simpan token.

### ☁️ Token terpusat di PocketBase

- Secret PB **`ARGOCD_TOKEN`** (collection `secrets`, scope `argocd`, `expires_at` dan
  `rotated_at` terisi) diperbarui setiap login SSO, termasuk auto-login saat token kedaluwarsa.
- Salinan lokal di `~/.build-q/auth.json` (perm 600).
- Prioritas: env / secret PB yang di-hydrate → `~/.build-q/auth.json`. Token yang kedaluwarsa
  (klaim `exp` JWT, margin 5 menit) dilewati.
- Kegagalan push ke PB tidak membatalkan login; status PB ditampilkan.

### ⌨️ `bq argocd <args>` — official argocd CLI inline

Menjalankan `argocd` dengan `--server`, `--grpc-web`, dan `--grpc-web-root-path` dari
`ARGOCD_API_URL`. Token dikirim lewat env `ARGOCD_AUTH_TOKEN` (tidak muncul di argv / `ps`).
Bila token tidak ada dan terminal interaktif, login SSO dijalankan otomatis.

```bash
bq argocd app list
```

## Changed

- **Auto-login ArgoCD** (`ARGOCD_AUTO_LOGIN`, saat 401) kini memanggil `bq --argocd-auth-sso`,
  tidak lagi `argocd-app token-login`.
- **`auth.json` menjadi satu store:** login/logout PB tidak lagi menghapus key lokal seperti
  `ARGOCD_TOKEN`. Logout hanya menghapus sesi PB; file dihapus bila tidak ada key lain.
- `is_enabled()` (PB API) hanya aktif bila sesi PB ada, bukan sekadar file `auth.json` ada.

## Removed

- Knob **`ARGOCD_AUTH_FILE`** dihapus; lokasi token dikunci ke `~/.build-q/auth.json`.
  Nilai di `.env` diabaikan.

## Catatan

- `argocd-app` (di luar repo, `~/.agents/bin/`) masih memakai `~/.pi/agent/auth.json`.
- Tindak lanjut: lihat issue [#26](https://github.com/mamatnurahmat/build-q/issues/26).
