# build-q v0.2.1

Rilis patch setelah v0.2.0 dengan dua tambahan:

1. **E2E CI/CD di web chat** (`bq --serve`) memakai credential masing-masing pengguna
   dari PocketBase (PR #15).
2. **Mapping kube context ↔ namespace terpusat di PocketBase.** Jev memakainya untuk
   memilih context terdekat (PR #16).

## New

### 🔭 E2E CI/CD di web chat — `bq --serve`

- Endpoint baru: `POST /api/e2e`, `GET /api/e2e/stream/<id>` (SSE), dan
  `GET /api/e2e/scenarios`. Semuanya read-only, sehingga tetap aktif dengan `--serve-no-exec`.
- UI: tombol **🔭 E2E**, perintah `/e2e REPO REF` dan `/e2e --sim`, serta rantai tahap yang
  diperbarui langsung. Titik putus ditandai, dan setiap tahap punya kartu detail, log, dan saran.
- **Credential per pengguna, tanpa state di server.** Setiap request membawa header
  `X-PB-Token` dari login SSO GitHub (Dex) di browser. Server lalu mengambil credential milik
  pengguna tersebut dari PocketBase: `GITHUB_TOKEN`, `KUBECONFIG*_B64`, `ARGOCD_TOKEN`, dan
  config ArgoCD. Kubeconfig ditulis ke direktori sementara (izin 0700) dan dihapus setelah job
  selesai. Server **tidak** memakai cadangan dari env, `.env`, `auth.json`, cache, atau
  kubeconfig milik server.

### ☸️ Knowledge kube context ↔ namespace di PocketBase

Sumber mapping adalah collection PocketBase `kube_cx` (context) dan `namespace` (relasi ke
`kube_cx`):

| Context | Namespace |
|---|---|
| `hw-dev` | default, develop-qoin, develop-ngenwal, develop-payout, develop-qoinhub, develop-saas, sandbox-qoin, jenkins-x |
| `hw-pro-p` | production-payout, argocd, develop-payout |
| `hw-pro-q` | production-qoin, staging-qoin |
| `hw-pro-u` | production-ngenwal, production-saas, staging-ngenwal |

Pengaruhnya ke Jev planner (`--tui` dan `--serve`):
- Param `kube_context` terisi otomatis dari namespace.
- Namespace yang belum terdaftar memakai prefix terdekat: `develop-*` dan `sandbox-*` ke
  `hw-dev`, `staging-*` ke `hw-pro-q`. Namespace `production-*` yang tidak dikenal sengaja
  tidak ditebak.
- Bila masih belum terisi, Jev memilih context dengan bantuan mapping di atas. Untuk namespace
  yang ada di lebih dari satu context (mis. `develop-payout`), pilihan Jev dibatasi ke
  kandidatnya saja.
- MCP resource baru: `bq://kube-contexts`.

## Improved

- `bq --tui-pull` dan `/refresh` di TUI ikut mengambil ulang mapping kube context.
- `bq --tui-sync <seed>` kini juga melakukan upsert ke `kube_cx` dan `namespace`. Di seed,
  field `namespace.kube_cx` cukup diisi nama context; ID record dicari otomatis.
- `config.build_config(getenv)`, `github_api.use_token`, dan `e2e.use_credentials` (berbasis
  ContextVar) memungkinkan credential per request. Perilaku CLI tidak berubah.

## Configuration

Mapping di-cache di `~/.build-q/.kube-cx-cache.json` dengan TTL yang sama seperti katalog TUI
(`BUILD_Q_TUI_CACHE_TTL`, default 1 jam). Bila PocketBase tidak bisa dihubungi, bq memakai
cache lama, lalu mapping bawaan.
