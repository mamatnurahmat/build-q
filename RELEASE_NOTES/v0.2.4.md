# build-q v0.2.4

Rilis patch: **saran manifest satu aplikasi** mengikuti konsep GitOps saat ini, **template
standar terpusat** di PocketBase, dan **skenario uji leave-one-out** yang menjamin saran tidak
mengubah core manifest yang sudah berjalan. Desain lengkap: [PRD-manifest.md](../PRD-manifest.md);
panduan: [E2E-MANIFEST.md §14–15](../E2E-MANIFEST.md).

## New

### 🧱 `bq --manifest-init <repo> <namespace>`

```bash
bq --manifest-init pay-be-topup-manager production-payout
bq --manifest-init pay-be-topup-manager sandbox-payout --out-dir ./gitops-draft --export-md init.md
```

- Env = prefix namespace. Ref source: develop/staging/sandbox → branch yang sama; production →
  tag `v*` semver tertinggi. Branch/tag belum ada (aplikasi baru) → branch default repo, dengan
  catatan bahwa tag image berubah setelah pipeline env berjalan.
- Path GitOps sama dengan saran rollout pipeline: `<infra>/<namespace>/<DEPLOYMENT>_deployment.yaml`
  dari `cicd.json`; branch GitOps = env atau `main`. `<env>` saja tetap diterima (namespace dari
  `cicd.json` PROJECT).
- **Manifest sudah ada** → hasil cek tahap Manifest + saran perbaikan (tidak pernah menimpa).
- **Belum ada** → Deployment + Service dari template PB → sample tetangga → generator; kerangka
  Secret hanya untuk Secret yang belum ada di cluster; baris `resources` kustomization atau
  `kustomization.yaml` baru. Catatan bila namespace belum punya Secret/`regcred` atau nodepool
  belum terdaftar.
- `--out-dir` menulis file dengan struktur path GitOps, siap diajukan lewat PR.

### 🧩 Template standar — `bq --manifest-template` + PB `build_q_manifest_templates`

```bash
bq --manifest-template all
bq --tui-sync ~/.build-q/manifest-templates-seed.json
```

- Template Deployment + Service per `infra × namespace × jenis aplikasi`, dibangun dari manifest
  GitOps `main` yang lolos semua kriteria standar, dengan konvensi port Service mayoritas.
- Dipakai lebih dulu oleh `--manifest-init` dan saran Manifest (`--e2e`, `--manifest-check`)
  sebelum sample tetangga → hasil konsisten.
- Collection baru (baca: login, tulis: superuser); seed disimpan lokal, **tidak** di repo.
- Saat ini 15 template (production-qoin, production-ngenwal, production-payout, staging/develop-ngenwal, staging-qoin).

### 🧪 Skenario uji — `bq --manifest-verify <namespace>`

```bash
bq --manifest-verify production-qoin --export-md verify.md --export-json verify.json
```

Leave-one-out: tiap Deployment dianggap belum ada, di-generate dari template/sample lain, lalu
field inti dibandingkan dengan aslinya (setelah patch kustomization). Status: match ·
match (asli tidak standar) · **diff** (regresi, exit 1) · unik · skip.

## Improved

- **Label `project` standar = akhiran namespace** (`production-qoin` → `qoin`), sesuai konvensi
  dominan di GitOps `main`. Sebelumnya prefix nama aplikasi, yang bisa mengubah selector.
- **Saran dari sample**: env & replicas selalu standar; nama Secret config dinormalkan; mount
  config tidak ganda; jenis aplikasi (akhiran) diutamakan, lalu sample berlabel standar;
  konvensi port klien tetap (mis. `80 → 8810`) diikuti; `regcred` hanya untuk image privat.
- **Deteksi stack .NET** juga dari mount `appsettings.*.json`.
- `bq --tui-sync` mendukung `build_q_manifest_templates`.

`env: staging` di production, label non-standar), bukan kesalahan generator. Hasil awal sebelum
perbaikan: 1/50 match di production-qoin.
