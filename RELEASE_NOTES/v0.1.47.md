# build-q v0.1.47

Rilis ini memperkenalkan **`bq --e2e`** — analisa CI/CD **end-to-end** satu commit dari
trigger hook → pipeline Tekton → GitOps → ArgoCD, lengkap dengan **titik putus** dan saran
tindak lanjut, plus **mode simulasi** 17 skenario tanpa cluster. TUI `bq --tui` juga
diperkuat (stabil, audit log, riwayat input) dan penilaian risikonya kini **selaras dengan
MCP server** lewat satu kebijakan bersama.

> ℹ️ Ini rilis PyPI pertama sejak v0.1.43, sehingga juga membawa **MCP server `bq --mcp`**
> (v0.1.44–v0.1.46: 18 tools, 4 resources, 3 prompts). Lihat README bagian 15 dan
> [`MCP-SETUP.md`](../MCP-SETUP.md).

## New

### `bq --e2e` — "Commit saya kok belum live?"

```bash
bq --e2e pay-be-topup-manager develop
bq --e2e Qoin-Digital-Indonesia/pay-be-topup-manager v1.4.2
```

Read-only. Menelusuri satu commit dan berhenti menebak di mana alurnya putus:

| Tahap | Sumber data | Contoh temuan |
|---|---|---|
| Source | GitHub commit API, `cicd.json` | ref → SHA, ENV & tag image (aturan sama dgn Tekton) |
| Trigger | Actions run `trigger-ci.yml` (per head SHA), webhook `cicd-hw.qoin.id/hook` | Action gagal karena secret belum diset, trigger belum terpasang |
| Pipeline | PipelineRun `webhook-<repo>-*` (label `repo`/`ref`, anotasi `commit_sha`) + results TaskRun di `JX_KUBE_CONTEXT` | step gagal + 15 baris log terakhir (secret disamarkan), commit belum diproses |
| GitOps | YAML di branch ENV (`develop`/`staging`/`sandbox`), PR ke `main` untuk tag `v*` | manifest belum di-bootstrap, PR belum merge, tag ditimpa commit lain |
| ArgoCD | Application di `ARGOCD_KUBE_CONTEXT` yang memantau folder file tsb | OutOfSync, auto-sync tertahan, override kustomize, Degraded, folder belum terdaftar |

Contoh keluaran (data nyata `hw-dev` / `hw-pro-p`):

```
🔭 E2E CI/CD: Qoin-Digital-Indonesia/plus-be-nonqris-manager @ develop (a18283e, ENV=develop, tag a18283e)

   ✅ Source → ✅ Trigger (hook) → ✅ Pipeline (Tekton) → ✅ GitOps → ⚠️  ArgoCD (deploy)
...
⚠️  ArgoCD (deploy): live 8594c0f, GitOps a18283e — Deployment OutOfSync
     • Application develop-qoin: sync=OutOfSync health=Healthy auto-sync=on
     💡 Auto-sync ON tapi belum menerapkan perubahan (operasi terakhir 2026-10-13T08:45:21Z) — ...

🎯 Titik putus: ArgoCD (deploy) — live 8594c0f, GitOps a18283e — Deployment OutOfSync
```

**Verdict & exit code** (aman dipakai di skrip/CI):

| Verdict | Arti | Exit |
|---|---|---|
| `healthy` | semua tahap relevan ✅ — commit sudah live | 0 |
| `broken` (titik putus FAIL) | trigger / pipeline / GitOps gagal | 1 |
| `broken` (WARN/RUNNING) atau `incomplete` | menunggu PR/sync/pipeline, atau ada tahap tak terperiksa | 2 |

Cluster yang tidak terjangkau (VPN, timeout 25 s) menghasilkan `incomplete` — laporan
**tidak pernah** menyatakan "sehat" bila ada tahap yang tidak bisa diperiksa. Repo FE
(`web/…`, Docker Compose) melewati tahap ArgoCD.

### `bq --e2e --simulate` — simulasi tanpa cluster

```bash
bq --e2e --simulate list                   # daftar 17 skenario
bq --e2e --simulate                        # self-test semua skenario (exit 1 bila ada yang meleset)
bq --e2e --simulate pipeline-build-failed  # laporan lengkap 1 skenario, exit code = mode nyata
```

Dunia tiruan GitHub + Tekton + ArgoCD (bentuk objek mengikuti cluster nyata) mencakup semua
jenis titik putus: trigger gagal/tidak ada, build gagal, pipeline berjalan/belum diproses,
manifest belum ada, YAML ditimpa, PR rilis belum merge, OutOfSync, override kustomize,
Degraded, Application tidak ada, FE Compose, cluster tak terjangkau, ref tidak ada, plus
alur sehat develop & rilis production. Tiap skenario menegaskan status tahap, titik putus,
verdict, serta frasa yang **wajib** / **dilarang** muncul di laporan.

### TUI: `/e2e` dan `/e2e --sim`

```text
you: /e2e pay-be-topup-manager develop
you: /e2e --sim                       # tabel skenario
you: /e2e --sim gitops-pr-open
```

Ditampilkan sebagai rantai status + panel per tahap, titik putus digarisbawahi; tercatat di
audit log (event `e2e` / `e2e_sim`). Tool katalog baru **`bq_e2e`** di
`scripts/build-q-seed.json` agar permintaan natural ("kenapa develop X belum live?")
diarahkan ke fitur ini — aktif setelah `bq --tui-sync scripts/build-q-seed.json`.

## Improved — `bq --tui`

- **Stabil**: error dalam satu giliran (respons Jev tidak valid, tool di luar katalog,
  template rusak, Ctrl+C saat isi param) tidak lagi mematikan sesi.
- **Audit log** `~/.build-q/.tui-audit.log` (JSON lines, rotasi 5 MB × 3): `start`,
  `decide`, `skip`, `execute`, `error`, `e2e`, `e2e_sim`.
- **Riwayat input** (panah atas/bawah) di `~/.build-q/.tui-history`.
- Slash command baru: `/refresh` (ambil ulang katalog), `/set KEY` (value diketik
  tersembunyi).
- Request ke provider Jev disamarkan dulu (token GitHub, `sk-…`, age secret key, `Bearer …`,
  `*_TOKEN=` / `*_PASS=`).
- Label sumber katalog akurat (`pb` / `cache` / `stale-cache` / `bootstrap`); cache katalog
  in-process ikut TTL.
- Param kosong di template dirender `<nama>` + peringatan, bukan crash.

## Improved — selaras dengan MCP server

- **`build_q/tool_policy.py`** — satu tabel tier risiko (`read` / `local` / `external`)
  untuk 18 tool MCP:
  - MCP server kini mengirim **`ToolAnnotations`** standar (`readOnlyHint`,
    `destructiveHint`, `idempotentHint`, `openWorldHint`) sehingga klien MCP bisa
    membedakan tool aman vs berisiko secara otomatis.
  - TUI dan `bq --serve` memetakan perintah `bq --flag …` ke tool MCP padanannya; tier
    `local`/`external` ⇒ **RISKY** (konfirmasi default *No*). Tier MCP hanya menaikkan
    risiko, tidak pernah menurunkan.
- **`build_q/audit.py`** — format audit log bersama MCP & TUI (JSON yang selalu valid,
  rotasi file). Sebelumnya log MCP bisa menghasilkan JSON rusak bila pesan mengandung tanda
  kutip.

## Fixed

- ArgoCD `syncPolicy.automated: {}` kini dibaca sebagai auto-sync **ON**.
- `bq --e2e` tidak lagi menyarankan `--gitops-set-image` untuk tag yang image-nya belum
  pernah ter-build.
- `bq --tui-ls` menampilkan sumber katalog yang benar saat memakai cache lama.

## Behavior changes

- **`bq --tui` tidak lagi membaca `.env` di direktori kerja** (fallback legacy) — menjalankan
  TUI di dalam repo aplikasi tidak ikut memuat secret aplikasi. Konfigurasi tetap dari
  `~/.build-q/.env`.
- Perintah yang terpetakan ke tool MCP berisiko kini **RISKY** di TUI/serve walau record
  katalog `risky=false` — mis. `bq_sops_decrypt` dan build tanpa `--dry-run`
  (`bq_build_no_push`).

## Configuration

Opsional di `~/.build-q/.env` (dibaca `bq --e2e`, akses baca saja):

```env
ARGOCD_KUBE_CONTEXT=hw-pro-p
ARGOCD_NAMESPACE=argocd
```

`bq --e2e` juga memakai `JX_KUBE_CONTEXT` / `JX_KUBE_NAMESPACE` (default `hw-dev` /
`jenkins-x`) dan `GITOPS_REPO` yang sudah ada.
