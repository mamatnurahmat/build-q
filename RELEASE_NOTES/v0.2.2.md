# build-q v0.2.2

Rilis patch yang menambah tahap **Manifest** di `bq --e2e`: memastikan pasangan
Deployment ↔ Service ↔ Secret aplikasi di repo GitOps sudah benar, lalu memberi **saran YAML**
yang disalin dari manifest asli di repo GitOps `main:cce/<namespace>`. Standar rule-nya
disimpan terpusat di PocketBase.

Dokumentasi lengkap: [E2E-MANIFEST.md](../E2E-MANIFEST.md).

## New

### 🧩 Tahap Manifest di `bq --e2e` (PR #18)

Rantai e2e kini: `Source → Trigger → Pipeline → GitOps → Manifest → ArgoCD`. Berjalan di
CLI, TUI `/e2e`, dan web (`bq --serve`), dan bersifat read-only.

Yang diperiksa, pada **hasil akhir kustomization** folder:

- `spec.selector.matchLabels` termuat di label pod; selector Service cocok dengan pod.
- `targetPort` bernama ada di `containerPort` (`targetPort` angka yang tidak dideklarasikan
  hanya warn).
- Service ada untuk Deployment yang membuka port (worker tanpa port tidak wajib).
- File deployment/service terdaftar di `resources:` kustomization.yaml.
- `imagePullSecrets: regcred` untuk image privat `loyaltolpi/…`, setelah patch kustomization.
- Secret yang dirujuk pod (`file-config-<app>`, `envFrom`, `secretKeyRef`, `regcred`) **ada**
  di namespace. Hanya nama yang dibaca (`kubectl get secrets -o name`), isi Secret tidak pernah.
- Saran standar (warn, bukan titik putus): label standar `app/env/project/role` dan volume
  `file-config-<app>` (config yang masih *baked* di image).

Hal yang ikut diperhitungkan:

- `namespace:` di kustomization menimpa `metadata.namespace`. Misalnya folder
  `cce/staging-ngenwal` dinilai sebagai namespace `production-ngenwal`.
- Patch JSON6902 (`add`/`replace`/`remove`) diterapkan sebelum pemeriksaan.
- Cluster untuk cek Secret dipilih dari `destination` Application ArgoCD, lalu mapping
  `kube_cx` per namespace. Untuk namespace ambigu, dipakai cluster yang menjalankan
  Deployment. Path `k8s/` (SLS) tidak memakai mapping CCE.

Status tahap: temuan **critical** → ❌ (titik putus, exit code 1); Secret belum bisa
diverifikasi → ⏭️ (verdict *incomplete*, exit code 2); hanya **warn** → ✅ dengan
`· saran standar: …`.

### 📝 Saran YAML dari sample GitOps `main:cce`

- **Manifest baru** (Deployment dan/atau Service yang belum ada) disalin dari aplikasi
  tetangga terdekat di `main:cce/<namespace>`. Kandidat diurutkan dari role
  `-manager`/`-module`, project, dan jenis `be`/`fe` yang sama; sample yang dipakai harus
  punya Service, terdaftar di kustomization, dan lolos rule critical.
- Penyesuaian: nama, label standar, image + tag dari tahap Source, `PORT` cicd.json, stack
  Go/.NET (args + mount `/app/.env` / `/app/appsettings.<env>.json`), nodepool sesuai role,
  dan `regcred` bila tidak disuntikkan patch.
- Field runtime dibuang: annotation Helm/ArgoCD, `status`, `clusterIP`, label
  `app.kubernetes.io/managed-by: Helm`, dan label tracking ArgoCD
  `app.kubernetes.io/instance` (agar resource baru tidak dianggap milik Application lain).
- **Perbaikan file lama**: diff minimal (urutan key asli dipertahankan), `matchLabels`
  immutable dipertahankan, dan `port` Service tidak pernah diubah. `targetPort` bernama yang
  salah diarahkan ke nomor port Service bila dideklarasikan container; bila tidak, saran
  Deployment menambah `containerPort` bernama tersebut.
- **Kerangka Secret** `file-config-<app>` (`.env` / `appsettings.<env>.json`). Isinya diisi
  dari file config dan tidak boleh di-commit plaintext.
- Tanpa sample yang memenuhi syarat, dipakai generator standar Qoin.

### 🗂️ Rule standar di PocketBase — `build_q_anomaly_rules`

- Collection baru (baca: pengguna login, tulis: superuser) berisi **53 rule** dari
  `scripts/anomaly-rules-seed.json`. Tahap Manifest memakai 12 di antaranya: 10 diperiksa,
  2 hanya dipakai `params`-nya (nodepool per namespace dan sumber sample).
- Severity, `active`, deskripsi, dan `params` (label wajib, prefix secret, mount path,
  nodepool, prefix image privat, `branch`/`infra` sample) diatur dari PB tanpa rilis ulang:
  edit seed lalu `bq --tui-sync scripts/anomaly-rules-seed.json`.
- Sumber: PB → cache `~/.build-q/.anomaly-rules-cache.json` → default bawaan.

### 🤖 Penilaian Jev untuk tahap Manifest

Bila ada temuan, Jev dipanggil satu kali dengan nama deployment, namespace, dan daftar
temuan (tanpa YAML/isi Secret). Hasilnya: `Jev: siap melayani traffic N%, bereskan dulu:
<rule>`. Aktif di TUI dan web; di CLI matikan dengan `--no-jev`. Status tahap tetap
ditentukan rule deterministik.

## Improved

- **Mapping `kube_cx`** memuat field `server`, sehingga `destination.server` Application
  ArgoCD bisa dipetakan ke context. Cache `~/.build-q/.kube-cx-cache.json` naik ke format v2;
  cache lama otomatis diambil ulang.
- **`bq --tui-sync`** bisa melakukan upsert ke `build_q_anomaly_rules` (kunci `rule_name`)
  dan membersihkan cache rule & `kube_cx`.
- **TUI** menampilkan saran YAML sebagai panel ber-highlight; **web** menambah tahap
  *Manifest* di rantai e2e dan menampilkan YAML di kartu tahap; **CLI** mencetak blok
  `📝 Saran YAML — …`.
- **Simulasi** `bq --e2e --simulate` naik dari 18 ke 23 skenario: `manifest-selector-mismatch`,
  `manifest-service-missing`, `manifest-not-in-kustomization`, `manifest-secret-missing`, dan
  `manifest-baked-config`. Dunia simulasi kini memuat kustomization dan aplikasi tetangga
  sebagai sumber sample.
- **`--no-jev`** berlaku juga untuk `--e2e`.

## Behavior changes

- **Tahap baru bisa menjadi titik putus.** Commit yang sudah live tetapi manifest-nya
  bermasalah (mis. Service tanpa endpoint, Secret tidak ada) kini dilaporkan `broken` dengan
  exit code 1.
- **Verdict bisa *incomplete*** bila Secret tidak bisa diverifikasi di cluster (VPN mati,
  kubeconfig tanpa context `hw-*`).
- **`--e2e` di CLI memanggil Jev** bila tahap Manifest punya temuan (memakai
  `TYPESAFE_API_KEY`). Gunakan `--no-jev` untuk skrip/CI.
- **`pyyaml` menjadi dependency wajib** (sebelumnya opsional lewat extra `anomaly`) dan
  terpasang otomatis saat upgrade.
