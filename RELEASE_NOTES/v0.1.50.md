# build-q v0.1.50

Rilis ini menambahkan **`--cloud`**: build & push image lewat **Docker Build Cloud** (produk
Docker Hub, org `loyaltolpi`) langsung dari laptop, termasuk dengan engine **OrbStack**.

## New

### `--cloud` — build via Docker Build Cloud

```bash
bq my-service develop --remote --cloud             # build dari git (remote repo#ref)
bq my-service develop --remote --cloud --rebuild   # paksa build walau image sudah ada
bq --cloud                                         # folder kerja saat ini
bq my-service develop --remote --cloud --dry-run   # tampilkan perintah, tanpa kredensial
```

- **Skip otomatis.** Sebelum build, `bq` mengecek apakah image sudah ada di Docker Hub memakai
  kredensial PocketBase Anda. Jika sudah ada, build di-skip. Build hanya berjalan lagi dengan
  `--rebuild`.
- **Builder cloud dibuat otomatis** (`cloud-loyaltolpi-qoin-build` → `loyaltolpi/qoin-build`)
  bila belum ada.
- **Kredensial** `DOCKERHUB_USER` / `DOCKERHUB_TOKEN` diambil dari PocketBase (owner-only).
  Token dikirim lewat stdin ke `docker login`, tidak pernah masuk argumen atau log.
- **Context:**
  - `--remote`: build dari git `repo#ref`, tanpa clone lokal (`GIT_AUTH_TOKEN` diteruskan untuk
    repo privat).
  - tanpa `--remote`: folder kerja saat ini.

## Penting: buildx resmi diperlukan

Buildx bawaan OrbStack/Homebrew tidak memuat driver `cloud` (`failed to find driver "cloud"`).
`--cloud` memakai buildx resmi **≥ v0.38.0**, yang dicari di:

1. `--cloud-buildx PATH`
2. `$BQ_BUILDX_BIN`
3. `~/.build-q/bin/docker-buildx`

Pasang buildx resmi ke lokasi ketiga agar otomatis terdeteksi. Engine lokal (OrbStack, Docker
Desktop, colima) tetap bebas dipakai untuk `docker login`.

### Flag baru

| Flag | Default | Keterangan |
|---|---|---|
| `--cloud` | — | Aktifkan build via Docker Build Cloud |
| `--cloud-builder ORG/NAME` | `loyaltolpi/qoin-build` (env `CLOUD_BUILDER`) | Endpoint Docker Build Cloud |
| `--cloud-buildx PATH` | `~/.build-q/bin/docker-buildx` (env `BQ_BUILDX_BIN`) | Path buildx resmi |

## Testing

**338 tests** passed (1 skipped bila MCP SDK tidak terpasang). `test_cloud_build.py` (+15) memakai
buildx dan docker palsu di PATH: urutan login → buat builder → build, token lewat stdin, config
sementara dihapus, skip/`--rebuild`, context remote diteruskan, dan kesalahan yang jelas bila
buildx atau kredensial tidak ada.

## Upgrade

```bash
pipx upgrade build-q
bq --version                 # build-q 0.1.50
# opsional: pasang buildx resmi untuk --cloud
mkdir -p ~/.build-q/bin && curl -L -o ~/.build-q/bin/docker-buildx \
  https://github.com/docker/buildx/releases/download/v0.38.0/buildx-v0.38.0.darwin-arm64 \
  && chmod +x ~/.build-q/bin/docker-buildx
```
