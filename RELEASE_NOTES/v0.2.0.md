# build-q v0.2.0

Rilis besar pertama sejak v0.1.47. Fokus v0.2.0:

1. **Login wajib.** Setiap perintah `bq` kini membutuhkan sesi `bq auth login` yang valid.
2. **Build cloud** lewat Docker Build Cloud (`--cloud`), kompatibel dengan OrbStack.
3. **Login SSO GitHub** untuk PocketBase devops, serta pengambilan credential sendiri.
4. Pemeriksaan kesiapan (`--doctor --cloud`) dan beberapa perbaikan pada `--e2e`, `--pr-fix`, dan TUI.

> ⚠️ **Perubahan perilaku:** perintah `bq` kini memerlukan login SSO. Lihat bagian
> *Behavior changes* dan *Migration* sebelum upgrade, terutama untuk skrip atau CI yang
> sebelumnya memakai `PB_API_USER` / `PB_API_PASS`.

## New

### 🔒 Login wajib untuk setiap perintah `bq`

```bash
bq auth login      # SSO GitHub (browser), token disimpan di ~/.build-q/auth.json (perm 600)
bq auth status     # tampilkan & validasi token ke server
```

Tanpa sesi yang valid, perintah `bq` berhenti dengan pesan jelas:

```
🔒 bq membutuhkan login: belum login — jalankan `bq auth login`
```

**Aturan validasi:**
- Token harus **ada**, **belum kedaluwarsa** (berlaku 5 hari), dan **diterima server**.
- Token diperpanjang otomatis (`auth-refresh`) saat sisa umurnya kurang dari 1 hari.
- Verifikasi ke server di-cache **1 jam** (`verified_at` di `auth.json`), sehingga perintah
  tidak menambah latensi di setiap pemanggilan.
- Server menolak token (401/403/404) → perintah dihentikan dan diminta `bq auth login`.
- Server tidak terjangkau (mis. VPN belum aktif) → perintah tetap berjalan dengan peringatan,
  karena token lokal masih berlaku.

**Yang tetap bebas login:** `bq --help`, `bq --version`, `bq auth …`, dan `bq --doctor`
(yang justru menampilkan status login sebagai salah satu cek).

### `bq --cloud` — build & push via Docker Build Cloud

```bash
bq my-service develop --remote --cloud             # build dari git (context = repo#ref)
bq my-service develop --remote --cloud --rebuild   # paksa build walau image sudah ada
bq --cloud                                         # folder kerja saat ini
bq my-service develop --remote --cloud --dry-run   # tampilkan perintah, tanpa kredensial
```

- **Skip otomatis:** sebelum build, `bq` mengecek apakah image sudah ada di Docker Hub memakai
  kredensial PocketBase Anda. Jika sudah ada, build di-skip. Build hanya berjalan lagi dengan
  `--rebuild`.
- **Builder cloud dibuat otomatis** (`cloud-loyaltolpi-qoin-build` → `loyaltolpi/qoin-build`)
  bila belum ada.
- **Kredensial** `DOCKERHUB_USER` / `DOCKERHUB_TOKEN` diambil dari PocketBase (owner-only).
  Token dikirim lewat stdin ke `docker login`, tidak pernah masuk argumen atau log.
- **Context:** `--remote` membangun dari git `repo#ref` tanpa clone lokal (`GIT_AUTH_TOKEN`
  diteruskan untuk repo privat). Tanpa `--remote`, yang dibangun adalah folder kerja.

**Penting — buildx resmi ≥ v0.38.0 diperlukan.** Buildx bawaan OrbStack/Homebrew tidak memuat
driver `cloud` (`failed to find driver "cloud"`). `--cloud` mencari buildx di:

1. `--cloud-buildx PATH`
2. `$BQ_BUILDX_BIN`
3. `~/.build-q/bin/docker-buildx`

| Flag | Default | Keterangan |
|---|---|---|
| `--cloud` | — | Aktifkan build via Docker Build Cloud |
| `--cloud-builder ORG/NAME` | `loyaltolpi/qoin-build` (env `CLOUD_BUILDER`) | Endpoint Docker Build Cloud |
| `--cloud-buildx PATH` | `~/.build-q/bin/docker-buildx` (env `BQ_BUILDX_BIN`) | Path buildx resmi |

### `bq --doctor --cloud` — cek kesiapan build cloud (opsional)

Menjalankan pemeriksaan tambahan, tidak ikut `bq --doctor` biasa:
- buildx resmi dengan driver `cloud`,
- kredensial Docker Hub (dari PocketBase/env, token tidak ditampilkan),
- login Docker Hub (satu-satunya cek yang melakukan panggilan jaringan),
- builder cloud (peringatan bila belum ada; dibuat otomatis oleh `bq --cloud`).

Setiap cek yang belum lulus disertai saran perintah setup, disesuaikan dengan OS dan
arsitektur laptop (mis. `darwin-arm64`, `linux-amd64`).

`bq --doctor` (biasa) kini juga menampilkan cek **Login bq**.

### Login SSO GitHub untuk PocketBase devops — `bq auth` (sejak v0.1.48)

```bash
bq auth login                 # SSO GitHub (default, via Dex)
bq auth login --no-browser    # tampilkan URL saja
bq auth login --password      # alternatif email/password akun devops_users
bq auth status | refresh | logout
```

- Alur OAuth2 realtime PocketBase dengan PKCE dan verifikasi `state`.
- Token per-user, bukan superuser. Semua request PocketBase memakai token ini (dengan
  fallback ke `PB_API_USER`/`PB_API_PASS` hanya untuk API, bukan untuk gate CLI).

### Ambil credential sendiri — `bq auth list` / `bq auth get` (sejak v0.1.49)

```bash
bq auth list                                              # key yang boleh diakses (tanpa isi)
bq auth get KUBECONFIG_READONLY_HW_B64 > ~/.kube/config-readonly-hw
bq auth get GITHUB_TOKEN --scope github --env all         # bila key ada di beberapa scope/env
bq auth get SOME_B64 --raw > file.b64                     # tanpa decode base64
```

- Key `_B64` atau ber-tag `base64` di-decode otomatis.
- Hanya isi credential yang ditulis ke stdout; pesan ke stderr.
- Data diambil langsung dari server dengan token SSO Anda, sehingga aturan owner berlaku.

### Fallback REST API ArgoCD di `bq --e2e` (sejak v0.1.48)

Bila kubectl ke `ARGOCD_KUBE_CONTEXT` timeout, status Application dibaca lewat
`GET {ARGOCD_API_URL}/api/v1/applications`. Token 401 → `argocd-app token-login` otomatis
(hanya di terminal interaktif). Verdict menyebut "ArgoCD mengonfirmasi `<tag>` sudah live"
bila tahap ArgoCD ✅.

### `bq --pr-fix` — mode legacy (PR #12)

- `--init-legacy` dan `--pr-branch` untuk `--pr-fix-dockerfile`, sehingga perbaikan Dockerfile
  legacy bisa dibuat dalam branch tersendiri.

## Improved

- **Integrasi PocketBase** memakai `pb_api.get_token()`: token SSO lebih dulu, lalu fallback
  ke superuser (API saja). Token di-refresh otomatis.
- **`bq --pb-status`** menampilkan identitas dan masa berlaku token yang dipakai.
- **`bq --doctor`** menampilkan identitas dan sumber auth (`bq auth login` / superuser).
- **Registry check sebelum build** untuk `--cloud` memakai kredensial PocketBase, bukan login
  keychain (yang tidak punya scope pull untuk org ini, sehingga image yang sudah ada tidak
  terdeteksi).
- **`--clone` + `--cloud`** mengecek image di registry sebelum clone, sehingga clone dilewati
  bila image sudah ada.

## Fixed

- `bq --e2e`: ArgoCD tidak lagi dilaporkan "belum bisa dipastikan live" bila ArgoCD sudah
  mengonfirmasi tag yang diharapkan (verdict diperbaiki).
- `bq --cloud`: `--build-arg GITHUB_*` tidak lagi memuat nilai token di argumen proses; nilainya
  diambil dari environment (`--build-arg GITHUB_TOKEN`).
- `bq --cloud`: secret `netrc` lokal tetap dipakai pada build cloud (tidak dibuang).

## Behavior changes

- **Login SSO wajib untuk setiap perintah `bq`** (kecuali `--help`, `--version`, `auth`,
  `--doctor`). Tanpa login, perintah berhenti dengan exit code 1.
- **`PB_API_USER` / `PB_API_PASS` tidak lagi cukup untuk menjalankan `bq`.** Superuser fallback
  hanya berlaku untuk akses API PocketBase di dalam `bq`, bukan sebagai gate login CLI.
- `bq auth login` dan `bq auth logout` menghapus cache `~/.build-q/.pb-cache.json`, sehingga
  secrets diambil ulang dengan identitas baru.
- Secrets yang terlihat mengikuti hak akses user di server (lihat *Security*).
- `PB_API` aktif otomatis setelah `bq auth login` (tidak perlu diset di `.env`).

## Security

- Credential superuser tidak lagi diperlukan di laptop engineer, dan tidak cukup untuk
  menjalankan `bq`.
- Token disimpan di `~/.build-q/auth.json` dengan perm 600, ditulis secara atomik, dan hanya
  dikirim ke `PB_API_URL` tempat token diterbitkan.
- `state` OAuth2 diverifikasi, dan alurnya memakai PKCE.
- Token yang ditolak server tidak dipakai ulang. Pengguna diarahkan ke `bq auth login`.
- Kredensial Docker Hub dan GitHub tidak pernah masuk argumen perintah atau log.
- Aturan akses PocketBase devops diperketat (dikerjakan di server, terpisah dari paket ini):
  - Login SSO masuk sebagai role `view` (default) atau `admin`. User tidak bisa mengubah role sendiri.
  - Pendaftaran akun publik di luar SSO ditutup.
  - Credential (`secrets`, `hive_credentials`) owner-based: baca oleh pemilik atau admin; ubah/hapus
    hanya pemilik; kepemilikan tidak bisa dipindah.

## Migration

Dari v0.1.x:

```bash
pipx upgrade build-q
bq auth login          # login SSO GitHub sekali, berlaku 5 hari + auto-refresh
bq --doctor            # pastikan "Login bq" ✅
bq --doctor --cloud    # opsional: cek kesiapan build cloud
```

- Hapus `PB_API_USER` / `PB_API_PASS` dari `~/.build-q/.env` bila tidak lagi diperlukan.
- Untuk `--cloud`, pasang buildx resmi ≥ v0.38.0 ke `~/.build-q/bin/docker-buildx`
  (perintah lengkap ada di `bq --doctor --cloud`).

### Skrip dan CI

Karena login SSO sekarang wajib, skrip atau job CI yang hanya mengandalkan
`PB_API_USER` / `PB_API_PASS` akan berhenti dengan `🔒 bq membutuhkan login`. Pastikan job
tersebut memiliki sesi login yang valid, atau hubungi tim devops untuk jalur non-interaktif.

## Configuration

Opsional di `~/.build-q/.env` (semua punya default):

```env
# PocketBase
PB_API_URL=https://cicd-hw.qoin.id/devops
PB_API=true                         # opsional; aktif otomatis setelah bq auth login

# ArgoCD REST API (fallback bq --e2e)
ARGOCD_API_URL=https://cicd-hw.qoin.id/argocd
ARGOCD_TOKEN=                       # kosong → dibaca dari ARGOCD_AUTH_FILE
ARGOCD_AUTH_FILE=~/.pi/agent/auth.json
ARGOCD_AUTO_LOGIN=true

# Docker Build Cloud (--cloud)
CLOUD_BUILDER=loyaltolpi/qoin-build
BQ_BUILDX_BIN=~/.build-q/bin/docker-buildx
```

File yang dibuat/dikelola `bq`:

| File | Isi | Perm |
|---|---|---|
| `~/.build-q/auth.json` | token PocketBase (+ `verified_at`) | 600 |
| `~/.build-q/bin/docker-buildx` | buildx resmi ≥ v0.38.0 untuk `--cloud` | 755 |
