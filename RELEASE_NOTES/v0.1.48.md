# build-q v0.1.48

Rilis ini memperkenalkan **`bq auth`**: login ke PocketBase devops memakai **SSO GitHub**
(Dex, sama dengan ArgoCD). Hasilnya token per-user yang disimpan di `~/.build-q/auth.json`
dan dipakai otomatis untuk semua request PocketBase. Engineer tidak perlu lagi menyimpan
kredensial **superuser** (`PB_API_USER` / `PB_API_PASS`) di laptop. Identitas setiap request
kini jelas milik siapa, dan hak aksesnya mengikuti role user di server.

Rilis ini juga membuat `bq --e2e` tetap bisa membaca status ArgoCD ketika cluster tidak
terjangkau dari laptop, dengan fallback ke **REST API ArgoCD**.

## New

### `bq auth` — login PocketBase devops dengan SSO GitHub

```bash
bq auth login                 # default: SSO GitHub (browser) → token ke ~/.build-q/auth.json
bq auth login --no-browser    # tampilkan URL login saja (buka manual)
bq auth login --password      # alternatif: email/password akun devops_users
bq auth status                # tampilkan & validasi token ke server
bq auth refresh               # perpanjang token (auth-refresh)
bq auth logout                # hapus token + cache secrets
```

Contoh keluaran:

```
$ bq auth login
🔐 Login SSO GitHub (Dex) → https://cicd-hw.qoin.id/devops (devops_users)
   Buka URL berikut bila browser tidak terbuka otomatis:
   https://cicd-hw.qoin.id/argocd/api/dex/auth?client_id=pocketbase&...
✅ Login berhasil: <email> (role=admin) via oidc — berlaku s/d 2026-10-22T01:08:20Z
   Token disimpan di ~/.build-q/auth.json (perm 600)

$ bq auth status
   URL   : https://cicd-hw.qoin.id/devops (devops_users)
   User  : <email> (role=admin) via oidc — berlaku s/d 2026-10-22T01:08:20Z
✅ Token valid (server): <email> role=admin
```

#### Cara kerja login SSO

`bq auth login` memakai alur OAuth2 *all-in-one* bawaan PocketBase, sama dengan
`authWithOAuth2()` di PocketBase JS SDK. Tidak perlu port lokal, dan tidak perlu mendaftarkan
redirect URI baru di Dex.

1. `GET /api/realtime`: membuka koneksi SSE dan menerima `clientId` (event `PB_CONNECT`).
2. `POST /api/realtime`: subscribe ke topik `@oauth2`.
3. Membuka browser ke `authURL` provider `oidc` ("GitHub (Dex)") dengan
   `redirect_uri={PB}/api/oauth2-redirect` dan `state=clientId`. Alurnya memakai PKCE (S256).
4. Setelah user login di GitHub, PocketBase mengirim `{state, code}` lewat realtime.
   `state` diverifikasi harus sama dengan `clientId`. Kalau berbeda, login dibatalkan.
5. `POST /api/collections/devops_users/auth-with-oauth2` dengan `code` + `codeVerifier`.
   User baru otomatis terdaftar dengan role **`view`**.

Batas waktu login 5 menit. Ctrl+C membatalkan dengan rapi (exit 130).

#### Token store `~/.build-q/auth.json`

- Ditulis secara atomik dengan permission **600**.
- Isi: `pb_url`, `collection`, `method` (`oidc` / `password`), `token`, `exp`, `expires_at`,
  `saved_at`, dan ringkasan `record` (`id`, `email`, `full_name`, `role`, `verified`).
  Field internal seperti `tokenKey` tidak ikut disimpan.
- Token berlaku **5 hari**, dan **diperpanjang otomatis** (`auth-refresh`) ketika sisa umurnya
  kurang dari 1 hari.
- Token hanya dipakai untuk `PB_API_URL` tempat token itu diterbitkan. Kalau URL berganti,
  token tidak dikirim ke server lain.

### Fallback REST API ArgoCD di `bq --e2e`

Ketika `kubectl` ke `ARGOCD_KUBE_CONTEXT` gagal atau timeout (VPN, jaringan), tahap
**ArgoCD (deploy)** kini membaca `GET {ARGOCD_API_URL}/api/v1/applications`. Endpoint dan
token SSO-nya sama dengan yang dipakai MCP `argocd` dan skill `argocd-app`.

```
✅ ArgoCD (deploy): v1.2.15 sudah live (Healthy)
     • kubectl hw-pro-p gagal (kubectl timeout (25s) — context hw-pro-p) — dibaca via ArgoCD API https://cicd-hw.qoin.id/argocd
     • Application production-ngenwal: sync=Synced health=Healthy auto-sync=on
     • image live: loyaltolpi/ngenwal-apigateway:v1.2.15

❔ Analisa tidak lengkap — tidak bisa memeriksa: Pipeline (Tekton). ArgoCD mengonfirmasi v1.2.15 sudah live.
```

- **Token kedaluwarsa** (HTTP 401/403): di terminal interaktif, `bq` otomatis menjalankan
  `argocd-app token-login`, lalu mencoba sekali lagi. Perilaku ini tidak pernah berjalan di
  MCP/TUI (non-TTY), dan bisa dimatikan dengan `ARGOCD_AUTO_LOGIN=false`.
- Kalau kubectl **dan** API sama-sama gagal, laporan menampilkan kedua error dan menyarankan
  `argocd-app token-login`. Verdict tetap `incomplete`.
- Kalimat verdict kini menyebut "ArgoCD mengonfirmasi `<tag>` sudah live" bila tahap ArgoCD
  ✅, walaupun ada tahap lain yang tidak bisa diperiksa.

## Improved — integrasi PocketBase memakai token `bq auth`

Semua request PocketBase kini meminta token lewat satu fungsi, `pb_api.get_token()`, dengan
urutan prioritas:

| # | Sumber | Keterangan |
|---|--------|------------|
| 1 | `~/.build-q/auth.json` (`bq auth login`) | token user, di-refresh otomatis |
| 2 | `PB_API_USER` / `PB_API_PASS` di `.env` | **legacy** superuser, tetap didukung |
| 3 | — | error jelas: `belum login PocketBase — jalankan bq auth login` / `token ... kedaluwarsa` |

Yang memakai prioritas ini:

- hydrate secrets ke env (`load_config()` saat `PB_API` aktif) dan `bq --pb-login` / `--pb-pull`
- `pb_api.fetch_collection_records()`: dipakai bootstrap (`repo`) dan katalog TUI
- `bq --doctor`: kini menampilkan identitas dan sumber auth, misalnya
  `auth ok as <email> (bq auth login)` atau `(superuser .env)`
- `bq --pb-status`: baris `Auth` menampilkan user SSO dan masa berlaku token, atau superuser
  legacy

`bq --tui-sync` (seed katalog) **tetap** memakai superuser karena itu operasi admin.

## Behavior changes

- **PB API aktif otomatis setelah `bq auth login`.** Kalau `PB_API` tidak diset di
  `.env`/shell dan `~/.build-q/auth.json` ada, PB API dianggap aktif. `PB_API=false` tetap
  mematikannya secara eksplisit.
- **Secrets yang terlihat mengikuti hak akses user.** Dengan token SSO, `bq` hanya menerima
  secrets yang boleh dibaca user tersebut (lihat bagian berikut). User role `view` bisa
  menerima lebih sedikit secrets dibanding saat memakai superuser, dan sisanya diisi dari
  `~/.build-q/.env` lokal.
- `bq auth login` dan `bq auth logout` menghapus cache `~/.build-q/.pb-cache.json`, sehingga
  secrets diambil ulang dengan identitas yang baru.

## Server-side (PocketBase devops) — model akses

Fitur ini disertai pengetatan aturan akses di PocketBase devops, yang diterapkan terpisah
dari paket ini:

- Login lewat SSO masuk ke collection auth `devops_users` dengan role `view` (default) atau
  `admin`. User **tidak bisa mengubah role-nya sendiri**.
- Pendaftaran akun publik di luar SSO **ditutup**.
- **Credential** (`secrets`, `hive_credentials`) bersifat **owner-based**:
  - baca: pemilik (`owner` = email user) atau role `admin`
  - buat: `owner` wajib berisi email sendiri
  - ubah/hapus: hanya pemilik, dan kepemilikan tidak bisa dipindahkan
- Data operasional sensitif (agent, kanban, katalog repo/gitops) bisa ditulis hanya oleh
  `admin`.
- Superuser PocketBase tetap memiliki akses penuh.

## Configuration

Tambahan opsional di `~/.build-q/.env`. Semuanya punya default, jadi `.env` lama tidak perlu
diubah.

```env
# PocketBase — tidak ada key baru. PB_API_USER/PB_API_PASS kini opsional (fallback legacy)
PB_API_URL=https://cicd-hw.qoin.id/devops

# ArgoCD REST API (fallback bq --e2e saat kubectl gagal)
ARGOCD_API_URL=https://cicd-hw.qoin.id/argocd
ARGOCD_TOKEN=                         # kosong → dibaca dari ARGOCD_AUTH_FILE
ARGOCD_AUTH_FILE=~/.pi/agent/auth.json  # key ARGOCD_TOKEN (diisi `argocd-app token-login`)
ARGOCD_AUTO_LOGIN=true                # 401 → `argocd-app token-login` otomatis (TTY saja)
```

File baru di `~/.build-q/`:

| File | Isi | Perm |
|------|-----|------|
| `auth.json` | token PocketBase hasil `bq auth login` | 600 |

## Migration

Untuk engineer yang selama ini memakai `PB_API_USER` / `PB_API_PASS` superuser:

```bash
pipx upgrade build-q
bq auth login          # login SSO GitHub sekali, berlaku 5 hari + auto-refresh
bq auth status         # pastikan "Token valid (server)"
bq --doctor            # PB API: "auth ok as <email> (bq auth login)"
```

Setelah itu, `PB_API_USER` / `PB_API_PASS` sebaiknya **dikosongkan** dari
`~/.build-q/.env`. Kalau tetap diisi, keduanya hanya dipakai sebagai fallback ketika token SSO
tidak ada atau tidak berlaku.

## Security

- Kredensial superuser tidak lagi dibutuhkan di laptop engineer.
- Token disimpan dengan perm 600 dan ditulis secara atomik. Token hanya dikirim ke
  `PB_API_URL` tempat token itu diterbitkan.
- `state` OAuth2 diverifikasi, dan alurnya memakai PKCE.
- Token yang ditolak server (401/403) tidak dipakai ulang. User diarahkan ke
  `bq auth login`.
- Kalau refresh gagal karena **jaringan**, token lama yang masih berlaku tetap dipakai. Fitur
  tidak terputus hanya karena koneksi sesaat.
